# История Android: ошибки, решения и ограничения

## От форка до запуска

Android Studio была установлена, но сборочное окружение ещё требовало настройки.
Подключены SDK Command-line Tools, JDK 21, NDK и CMake. Архив инструментов Google
проверен по опубликованному SHA-256. Существующие принятые SDK-лицензии сохранены.
Для branded generic отделены applicationId, аккаунты, providers, БД и папка данных.

Растеризованные иконки сделаны из прозрачного icon2-clear через System.Drawing.
Первоначальные PNG.license внутри Android res мешали AAPT; они убраны из ресурсов,
лицензии PNG перенесены в REUSE.toml. Одноцветная маска уведомления оставлена в nodpi.
Добавлен отдельный adaptive round icon, но локальный lint всё ещё сообщает пять
IconLauncherShape для прежних launcher PNG: проблема не объявлена решённой.

Для строк выбран генератор через Variant API и обычный JVM XML API в app/build.gradle.kts.
Промежуточные варианты с отдельным Kotlin-script/buildSrc не вошли в итоговый проект.
Брендовые подписи генерируются для 58 локализаций без правки файлов переводов upstream.

## Интернет и проверки целостности

Обрывы сети приводили к DNS errors, reset соединений и ответам 403 Maven Central.
Подключено опциональное зеркало на Google Cloud Storage. Не отключались PGP/SHA
и не принимались новые checksums только ради успешной сборки.
Перестановка plugin-репозиториев вызвала другой checksum marker POM; её отменили.
PowerShell также мог принять диагностический stderr JVM за ошибку команды.
Окончательный APK проверяли отдельно от оболочки запуска Gradle.

## App isn't installed: ошибка нашего тестового запуска

Три resource/identity instrumented-теста прошли на Android 17.
Но для запуска был ошибочно использован эмулятор, на котором пользователь уже
проверял приложение и добавил рабочую учётную запись.
Gradle/UTP удалил тестовую установку целевого приложения после завершения.
Оставшийся значок начал выдавать App isn't installed; после восстановления APK
мог потребоваться новый вход. Это не было ошибкой самого launcher.

Добавлена защита build-local.ps1: явный serial, ровно одно устройство,
только чистый MSHost_Cloud_Automated AVD и отсутствие MSHost-аккаунтов.
На ручном эмуляторе/телефоне connected-тесты больше не запускаются.
Защита не создаёт AVD и не очищает пользовательские устройства.
Три теста проверяют идентификаторы, ресурсы/ссылки и ru/en labels, а не реальную синхронизацию.

## Открытая проблема авторизации

После восстановления приложения пользователь сообщил зависание на экране
«завершите процесс входа в вашем браузере» после успешного браузерного шага.
Был передан отдельный phone-test APK для проверки телефона.
Позднее пересобран APK только с новым default cloud.mshostcloud.org.
Успешное завершение входа на телефоне не зафиксировано; смена домена сама по себе
не считается исправлением login flow. При повторении нужны клиентские логи
с удалёнными токенами и проверка poll/return flow, а не слепая переустановка сервера.

## Смена домена и статические проверки

Default и ожидаемое значение existing branding test переведены на cloud.mshostcloud.org.
Новая сборка сохранила applicationId, versionCode, интерфейс, изображения и сертификат.
Новый URL подтверждён в двух ресурсах уже собранного APK, подпись проверена apksigner.

spotlessKotlinCheck прошёл после исправления CRLF в новом тестовом файле.
Полный lint пока падает на пяти IconLauncherShape. SpotBugs не смог запустить
анализирующий Java-процесс на Windows; useAuxclasspathFile добавлен, но полного решения не дал.
detekt сообщал LargeClass в существующем BackgroundJobManagerImpl upstream.
Эти результаты не объявляются успешным полным CI.
